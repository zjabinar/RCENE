# Geo data prep (packages/data/files)

The data session (`docs/projects/00-data.md`) runs on the user's Windows PC, where the archive lives under `D:\lgu_portal - GIS\`. It reads the archive, writes converted GeoJSON into `packages/data/files/`, and commits only that output. Apps serve `/data/<file>` from `packages/data/files` first and fall back to the fake fixtures in `packages/data/fixtures` file by file. So you can replace one layer at a time. A layer that is still a fixture shows a "Sample data" badge.

Every recipe below was run against fixture-based stand-ins for the archive files (a UTM 51N risk shapefile, OSM-style facility files, KML/KMZ), using mapshaper 0.6.121. The main ones are pinned in `scripts/data/data-tools.test.mjs`. Mapshaper's optional native modules (better-sqlite3, msgpackr-extract) are not built. Shapefile, GeoJSON, KML, CSV, FlatGeobuf and GeoPackage I/O work without them anyway, so no extra flag is needed.

## Hard rules (PRD §8.4)

- **Never read anything under `D:\monica`. Never copy anything from `C:\lgu_portal`**, because credential files sit at its root. Read only from `D:\lgu_portal - GIS\`.
- Use barangay-level and facility-level data only. No personal data, real or invented. Check KML descriptions for names and phone numbers (`--no-description` drops them).
- Credit every source in `sources.json`. The `/sources` page and the poster render it.
- 🟡 permission data (CDRRMO/CPDCO risk maps, CPDCO heritage KML) goes only into this **private** repo. Never push it to a public remote, gist or public deploy.
- Never copy raw sources into the repo. `.shp/.dbf/.prj/.kmz` are gitignored, but `.kml` and raw `.geojson` copies are not. Read straight from `D:\`, and stage in `$env:TEMP` if you must. `validate.mjs` fails on raw GIS files inside `packages/data/files`.
- 🟢 open data must be enough to ship. If a 🟡 layer is unusable, use the UP NOAH fallback (see the last section of this file).

## Output contract

| File (`LAYER_FILES` in `packages/data/src/layers.ts`) | Geometry | Properties to keep (`types.ts`); drop everything else |
|---|---|---|
| `boundary.geojson` | 1 polygon | `name` |
| `barangays.geojson` | 57 polygons | `name`, `psgc?`, `coastal?` |
| `land.geojson` | Samar outline around the city | `name` |
| `hazard-{flood,landslide,stormSurge,groundShaking,liquefaction}.geojson` | polygons | `hazard`, `level` (`low`/`moderate`/`high`/`veryHigh`), `sourceLayer?` |
| `facilities.geojson` | points | `id`, `name`, `kind` (`school`/`hospital`/`health`/`police`/`fire`/`townhall`/`other`), `barangay?`, `osmId?` |
| `heritage.geojson` | points | `id`, `name`, `category` (`heritage`/`eco-tourism`/`scenic`/`other`), `description?`, `barangay?` |
| `derived/*.json` | generated by `derive.mjs`; never edit by hand | |
| `sources.json` | one `SourceEntry` per file: `file, title, attribution, tier (open/permission), license?, url?, notes?` | |

The output must be WGS84 lon/lat, use 5 decimals (`precision=0.00001`), and total **under 3 MB**. Record the canonical layer chosen per hazard and the category→level mapping in the "Canonical layer per hazard and level mapping" section of `packages/data/README.md`. The templates are in [reference.md](reference.md).

## Setup (PowerShell, repo root)

```powershell
$GIS  = 'D:\lgu_portal - GIS'
$ADM  = "$GIS\data\region8\administrative_boundaries"
$RISK = "$GIS\gis_data\CATBALOGAN\Shapefiles (Mappers)\Risk Map"   # Flood, Landslide, Stormsurge, Groundshaking, Liquifaction
$FAC  = "$GIS\data\region8\critical_facilities"
$OUT  = 'packages/data/files'
```

**Quoting rule.** Never pass a double quote inside an argument. Embedded `"` can be stripped on the way through `pnpm.cmd` to node.
- Put each mapshaper JS expression in PowerShell single quotes: `-each 'level = levelOf($.properties)'`. Single quotes also keep `$` from being expanded.
- A short string literal can go in double quotes outside and single quotes inside: `-each "name='Samar (land)'"`. Use this form only when there is no `$`.
- Lookups and anything longer go in an `-include` file.
- Quote a whole `key=value with spaces` argument: `'where=level === null'`.
- A backtick ends a continued line, with no space after it.
- If an expression still arrives mangled (symptom: `ReferenceError: flood is not defined`), run `node node_modules/mapshaper/bin/mapshaper` with the same arguments.

## 1. Inspect before converting

```powershell
Get-ChildItem "$RISK\Flood" -Filter *.shp | Select-Object Name, Length
pnpm exec mapshaper "$RISK\Flood\Population to Flood Risk.shp" -info          # fields, CRS, bounds
pnpm exec mapshaper "$RISK\Flood\Population to Flood Risk.shp" -dissolve RiskLevel 'calc=n = count()' -o format=csv -   # every category + count
```

How to read `-info`:
- `CRS: +proj=utm +zone=51` with bounds near 700000,1300000 means UTM 51N. Reproject it.
- Bounds near 700000,1300000 with `CRS: +proj=longlat`, or with no CRS at all, means the `.prj` is wrong or missing. Add `init=EPSG:32651`.
- Bounds near 124.9,11.8 means it is already geographic, and `-proj wgs84` is a no-op.
- Garbled `ñ` in names means the `.dbf` encoding is wrong. Read the file with `-i "<file>.shp" encoding=latin1`.

`pnpm exec mapshaper-gui` opens a local viewer at http://localhost:5555 for comparing candidate layers.

## 2. Boundary and barangays (HDX GeoJSON, already WGS84)

```powershell
pnpm exec mapshaper "$ADM\catbalogan_city_boundary.geojson" -rename-fields name=ADM3_EN -filter-fields name `
  -o "$OUT/boundary.geojson" format=geojson precision=0.00001
pnpm exec mapshaper "$ADM\catbalogan_barangays.geojson" -rename-fields name=ADM4_EN,psgc=ADM4_PCODE -filter-fields name,psgc `
  -simplify dp interval=5 keep-shapes -o "$OUT/barangays.geojson" format=geojson precision=0.00001
```
`-rename-fields` takes `new=old`. Use the field names `-info` actually shows. Expect 57 barangays. Set `coastal` only from a source or local knowledge, never by guessing.

## 3. Land outline (offline basemap coastline)

```powershell
pnpm exec mapshaper "$ADM\<region 8 provinces or municipalities>.geojson" `
  -clip bbox=124.55,11.45,125.35,12.15 -dissolve2 -simplify 15% keep-shapes `
  -filter-islands min-area=0.5km2 remove-empty -each "name='Samar (land)'" -filter-fields name `
  -o "$OUT/land.geojson" format=geojson precision=0.00001
```
The bbox is the city plus about 0.3°. Keep the file under 150 KB: raise the simplification (`10%`) or `min-area=` if it is larger. The percentage simplification is fine here because exact outline shape doesn't matter, unlike in hazard zones.

## 4. Hazard layers (CDRRMO/CPDCO shapefiles, UTM 51N)

Choose **one** canonical layer per hazard. The default is *Population to {Hazard} Risk*. List its categories (step 1), then write one include file per hazard. Use `.txt`, not `.js`: the file is an object literal that oxlint can't parse.

```js
// scripts/data/include/levels-flood.txt
{
  // Canonical flood layer: "Population to Flood Risk" (CDRRMO/CPDCO). Category field: RiskLevel.
  HAZARD: "flood",
  SOURCE_LAYER: "Population to Flood Risk",
  levelOf: function (p) {
    var LEVEL_OF = { "Low": "low", "Moderate": "moderate", "High": "high", "Very High": "veryHigh" };
    return LEVEL_OF[String(p["RiskLevel"]).trim()] || null;
  }
}
```

```powershell
pnpm exec mapshaper "$RISK\Flood\Population to Flood Risk.shp" `
  -include scripts/data/include/levels-flood.txt `
  -proj wgs84 `
  -each 'level = levelOf($.properties), hazard = HAZARD, sourceLayer = SOURCE_LAYER' `
  -calc 'count()' 'where=level === null' `
  -filter 'level !== null' `
  -clip "$OUT/boundary.geojson" remove-slivers `
  -dissolve2 level copy-fields=hazard,sourceLayer allow-overlaps `
  -simplify dp interval=5 keep-shapes `
  -filter-fields hazard,level,sourceLayer `
  -o "$OUT/hazard-flood.geojson" format=geojson precision=0.00001
```

- **Missing or wrong `.prj`:** use `-proj wgs84 init=EPSG:32651`. `from=` is a deprecated alias for `init=`, so the older form `-proj from=EPSG:32651 wgs84` also works. It overrides a wrong `.prj` too, which was verified. Without it, a file with no `.prj` fails with "source coordinate system is unknown".
- **`-calc ... where=level === null`** prints how many features got no level. If that count is not zero, a category is missing from `LEVEL_OF`. Fix the mapping unless those categories really mean "no mapped risk".
- **`allow-overlaps` is required.** Plain `-dissolve2` hands overlapping areas to one level and can shrink a higher-level zone; this was verified. Overlaps are fine because the lookup takes the max level.
- **Simplify by distance for hazards.** `dp interval=5` (metres) keeps zone edges within 5 m. Raise it to 10–20 only to meet the 3 MB budget. `-simplify 15% keep-shapes` is relative, so on low-vertex polygons it can cut corners.
- Repeat for `landslide`, `stormSurge`, `groundShaking`, `liquefaction`. The archive folders are spelled `Stormsurge`, `Groundshaking`, `Liquifaction`.

### Mapping categories to levels

- Keep the source's order and don't add severity it doesn't have. A 3-class layer maps to `low`/`moderate`/`high`, never `veryHigh`.
- "None", "Not susceptible", "No data" and "Safe" map to `null`. Those features are dropped, so the area becomes **notInZone**, which is never "safe".
- When a value is ambiguous (a numeric code, or ground-shaking intensity), read the layer's legend or ask the user. Don't guess.
- Write every source value and its level, including the dropped ones, in `packages/data/README.md`. [reference.md](reference.md) has the table template and typical patterns.

## 5. Facilities (OSM GeoJSON, clipped to the city)

`scripts/data/include/facility-kinds.txt` maps OSM tags to `kind` and builds stable ids from OSM ids. The full text is in [reference.md](reference.md).

```powershell
pnpm exec mapshaper -i "$FAC\hospitals.geojson" "$FAC\schools.geojson" "$FAC\police.geojson" "$FAC\fire.geojson" combine-files `
  -include scripts/data/include/facility-kinds.txt `
  -each 'kind = kindOf($.properties, this.layer_name)' `
  -target type=polygon -points inner -target '*' `
  -merge-layers force name=facilities `
  -clip "$OUT/boundary.geojson" `
  -each 'osmId = osmIdOf($.properties), id = facilityId(osmId, this.id), name = nameOf($.properties, kind)' `
  -uniq id `
  -filter-fields id,name,kind,osmId `
  -o "$OUT/facilities.geojson" format=geojson precision=0.00001
```
Use the real file names from `Get-ChildItem $FAC`. Keep `-target type=polygon -points inner -target '*'` only when `-info` lists a polygon layer, because it errors when none exists. Before committing, check the kind counts: `-dissolve kind 'calc=n = count()' -o format=csv -`.

## 6. Heritage and eco-tourism points (CPDCO KML/KMZ)

```powershell
Get-ChildItem "$GIS\gis_data\CATBALOGAN" -Recurse -Include *.kml,*.kmz | Select-Object FullName
node scripts/data/kml-to-geojson.mjs "<heritage.kmz>" "$OUT/heritage.geojson" --id-prefix H-
node scripts/data/kml-to-geojson.mjs "<eco-tourism.kml>" "$OUT/heritage.geojson" --id-prefix H- --category eco-tourism --append
```
The script keeps Point placemarks only, gives each the id `<prefix>NNN`, and drops styles, altitude, lines and polygons. It prints how many of each it dropped. `--category` takes `heritage`/`eco-tourism`/`scenic`/`other`, and `--append` continues the numbering in an existing file. Read the descriptions before shipping.

## 8. Derive, validate, look at it

```powershell
node scripts/data/derive.mjs           # derived/barangay-hazard.json + derived/facility-hazard.json
node scripts/data/validate.mjs         # schemas, Samar bbox, ids, sources entries, sizes; exit 1 on errors

node scripts/smoke.mjs --app template  # build + offline browser check
Get-ChildItem $OUT -Recurse -File | Sort-Object Length -Descending | Select-Object Name, @{n='KB';e={[math]::Round($_.Length/1KB,1)}}
```
Re-run `derive.mjs` after any change to boundary, barangays, facilities or hazards. `validate.mjs` reports derived tables that no longer match their inputs. Over 3 MB, raise the hazard `interval=` first, then simplify `barangays`.

## Fallback: UP NOAH layer per hazard

When a CDRRMO layer is unusable (missing, broken geometry, no category field), use the Samar-wide NOAH layer under `noah_hazards\` for that hazard only. NOAH files are large: use the bigger-heap binary, and cut them down to a bbox around the city first. `bbox=` is in the data's units, so it goes after `-proj wgs84`.

```powershell
pnpm exec mapshaper-xl 8gb "<noah flood 100yr>.shp" -proj wgs84 -clip bbox=124.75,11.65,125.05,11.95 `
  -include scripts/data/include/levels-flood-noah.txt `
  -each 'level = levelOf($.properties), hazard = HAZARD, sourceLayer = SOURCE_LAYER' -filter 'level !== null' `
  -clip "$OUT/boundary.geojson" remove-slivers -dissolve2 level copy-fields=hazard,sourceLayer allow-overlaps `
  -simplify dp interval=10 keep-shapes -filter-fields hazard,level,sourceLayer `
  -o "$OUT/hazard-flood.geojson" format=geojson precision=0.00001
```
NOAH classes are usually numeric (1/2/3 for low/medium/high), so confirm them with `-info` and the NOAH legend. For flood, pick one return period, 100-year being the usual planning case. Record the substitution in the `sources.json` entry (tier `open`, attribution *UP NOAH Center*, `notes`: why the CDRRMO layer was replaced) and in the README.
